# 분류 사전과 추천 방식

## 사전 구성

2026-09-28 기준 12개 세부 분류 각각 100개, 총 1,200개의 관련 단어 및 짧은 표현을 사용한다. `public/keywords.mjs`가 사전 원본이다. 단일 명사뿐 아니라 증상, 시설명, 시민이 입력할 법한 구어체를 포함한다. 100개를 채우기 위해 띄어쓰기만 바꾼 표현은 넣지 않으며, 공백·기호를 제거한 뒤에도 카테고리 안의 100개 항목이 고유한지 테스트한다. 카테고리 간에 일부 표현이 겹치는 것은 허용한다.

공공기관이 제공한 '분류별 공식 키워드 100개'를 가져온 것은 아니다. 아래 공식 자료에서 분류 범위와 대표 시설·문제 명칭을 확인하고, 개발자가 동의어와 생활 표현을 직접 구성한 사전이다. 개별 표현 1,200개가 모두 공식 자료에 수록되어 있다는 의미가 아니다. 이 사전은 신고의 적법성이나 접수기관을 판정하지 않는다.

## 처리 과정

1. 입력과 사전을 NFKC로 정규화하고 영문을 소문자로 바꾼다. 띄어쓰기·기호 차이는 제거한다.
2. 각 표현에서 연속된 2·3·4글자 조각(character n-gram)을 추출한다. 예를 들어 '보도블록'에는 '보도', '도블', '블록', '보도블', '도블록', '보도블록'이 있다. '고장', '파손', '문제' 같은 일반적 조각은 제외한다.
3. 카테고리의 100개 표현을 하나의 문서로 취급한다. 특징의 유무를 TF=0 또는 1로 표현하고 IDF를 곱해 벡터를 만든다. IDF는 `1 + ln((분류 수 + 1) / (해당 조각이 있는 분류 수 + 1))`이다. 여러 분류에 흔한 표현보다 특정 분류에 나타나는 표현의 비중이 커진다.
4. 같은 사전으로 입력 문장의 벡터를 만든다. 코사인 유사도는 두 벡터 내적을 길이의 곱으로 나눈 값이다. 코사인 거리를 쓴다면 `1 - 코사인 유사도`이며 작을수록 가깝다. 여기서는 순위를 정하기 편하게 유사도를 사용한다.
5. 입력 조각 집합과 카테고리 조각 집합의 자카드 유사도 `교집합 크기 / 합집합 크기`도 구한다.
6. 추천 점수는 `0.7 × 코사인 유사도 + 0.3 × 자카드 유사도`이다. 가중치와 임계값은 프로젝트용 경험적 설정이며 학습된 확률이 아니다.
7. 사전 표현이 직접 일치하거나, 충분히 구별되는 3글자 이상 조각이 2개 이상(공유 조각 전체는 4개 이상) 있는 후보만 남긴다. 점수 0.025 이상이면서 최고 점수의 45% 이상인 후보를 최대 3개 제시한다.
8. 사용자는 추천된 항목 중 하나를 명시적으로 선택한다. 1개만 추천되더라도 자동으로 등록하지 않는다. 추천 근거가 없으면 전체 분류 목록을 열지 않고 입력 내용을 보완하도록 한다. 내용을 수정하면 이전 추천과 선택을 무효화한다.

수학 정의 참고: [자카드 유사도](https://scikit-learn.org/stable/modules/generated/sklearn.metrics.jaccard_score.html), [코사인 유사도](https://scikit-learn.org/stable/modules/metrics.html), [TF-IDF](https://sklearn.org/stable/modules/generated/sklearn.feature_extraction.text.TfidfVectorizer.html). 이 웹앱은 Python/scikit-learn을 실행하지 않고 동일한 표준 수식을 JavaScript로 계산한다.

## 예시와 한계

- '하수구에서 악취가 올라와요': 악취, 하수구 문제 후보를 제공한다.
- '도로 위에 쓰레기가 많이 쌓였어요': 도로라는 장소 표현보다 쓰레기 문제를 우선 추천한다.
- '고장나서 위험하고 불편해요': 대상이 불분명하므로 내용을 보완하도록 한다.

이는 의미를 이해하는 AI 모델이 아니라 조사한 사전과 글자 유사도를 이용한 추천이다. 완전히 새로운 동의어, 부정문('가로등 문제가 아니라...'), 비유, 여러 문제가 섞인 장문을 잘못 분류할 수 있다. '100개씩'이라는 사전 규모나 테스트 통과가 실제 정확도를 보장하지 않는다. 테스트 예문은 개발자가 구성한 회귀 검증용이며 독립된 실제 민원 평가 자료가 아니다. 실제 사용 중 놓치는 표현을 수집해 사전과 임계값을 수정해야 한다. 추천 점수는 정답 확률이 아니므로 사용자 화면에 백분율로 표시하지 않는다.

## 데이터 반영

체험 HTML은 내장 사전, 운영 앱은 Supabase `categories.keywords`를 사용한다. `node scripts/seed.mjs`로 100개 사전이 담긴 초기 `seed.sql`과 기존 DB용 `update-keywords.sql`을 생성한다. 기존 DB가 있다면 SQL Editor에서 `supabase/update-keywords.sql`만 실행하면 제보나 안내문은 그대로 두고 사전을 갱신할 수 있다. 이 작업에서 실제 Supabase DB 변경은 수행하지 않았다.
